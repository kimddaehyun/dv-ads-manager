# F-AutoSetup - 링크 하나로 광고 세팅 (AX 2호)

> 상태: **설계 완료, 구현 미착수** (2026-08-13)
> 정찰 원본: 메모리 `project_f_autosetup_mass_manage`, `reference_naver_tag_picker`
> 선행 AX: [F-Brief](./2026-07-16-f-brief-design.md) - AI 경계 원칙을 여기서 이어받되 더 넓게 쓴다

**F-Setup(세팅안 엑셀)과 다른 기능이다.** F-Setup은 *기존 계정을 읽어 제안서를 뽑는* 쪽이고, F-AutoSetup은 *링크를 받아 광고를 새로 만드는* 쪽이다. 방향이 정반대다.

---

## 1. 배경

신규 광고주 세팅은 AE가 하는 일 중 가장 품이 많이 드는 반복 작업이다. 상세페이지를 읽고, 업종을 파악하고, 키워드를 뽑고, 검색량을 확인하고, 그룹을 나누고, 소재 문구를 쓰고, 키워드를 하나씩 등록한다. 키워드 200개짜리 계정이면 하루가 간다.

이 중 **판단이 필요한 부분과 단순 반복인 부분이 섞여 있다.** 판단은 AE가 해야 하지만, "연관 키워드 500개 중 이 상품에 맞는 것 고르기"나 "고른 키워드를 하나씩 등록하기"는 사람이 할 이유가 없다.

### 관찰 1 - 재료가 이미 대부분 있다

| 필요한 것 | 이미 있는 코드 |
|---|---|
| 페이지에서 상품 정보 읽기 | 형제 프로젝트 `naver-tag-picker`의 `parseProductInfo` |
| 연관 키워드 + 검색량 | `src/shared/searchad.ts`의 `fetchRelatedKeywords` (시드 1개 → 최대 1000개) |
| 순위별 예상 입찰가 | background `GET_BID_ESTIMATE` + `src/shared/rank.ts` |
| 캠페인-그룹-소재-키워드 계층 다루기 | `src/features/setup/setup-data.ts` |
| AI 중계 (인증·토큰 기록 포함) | Edge Function `brief-compose` + Gemini |
| 파일을 페이지 업로드 칸에 주입 | `src/features/asset-bulk/image-file.ts` |

새로 만들 것은 **이것들을 잇는 파이프라인과 검토 UI**다.

### 관찰 2 - 대량등록이 가장 큰 덩어리를 해결한다

라이브 정찰 결과(§6), 네이버 대량관리는 **키워드 등록만** 지원한다. 캠페인·광고그룹·소재는 못 만든다.

처음엔 한계로 보였지만 실제로는 충분하다. 캠페인 1개 + 그룹 3~5개 + 소재 2~3개는 화면 자동화로 감당되는 양이고, **진짜 문제였던 키워드 수백 개가 CSV 업로드 한 번으로 끝난다.** 게다가 템플릿이 행마다 광고그룹ID를 받으므로 여러 그룹의 키워드를 한 파일에 섞어 올릴 수 있다.

### 관찰 3 - AI에게 키워드를 "만들라"고 하면 안 된다

LLM은 검색량 0인 키워드를 그럴듯하게 지어낸다. 실제 돈이 나가는 영역이라 치명적이다. 하지만 **"이 500개 중 이 상품에 맞는 걸 골라라"는 LLM이 아주 잘한다.** 발명은 막고 판단은 시키는 게 설계의 중심이다.

## 2. 무엇을 만드는가

```
링크 입력
   ↓
[1] 페이지 읽기          →  상품 정보 (사실)
   ↓
[2] AI 상품 이해         →  업종·타겟·강점  ← 여기서 먼저 확인받는다
   ↓
[3] 초안 생성            →  캠페인·그룹·소재·키워드 + 입찰가
   ↓
[4] 검토·수정           ← AE가 손보는 단계
   ↓
[5] 자동 세팅            →  화면 자동화 + CSV 업로드
```

### 범위 안

- 파워링크(`WEB_SITE`) 신규 세팅
- 네이버 스토어 상품 페이지 + 일반 웹페이지(자사몰 등) 읽기
- 캠페인 1개 + 광고그룹 N개 + 그룹당 소재 1~2개 + 키워드 최대 1000개/그룹
- 생성물 되돌리기
- **일시중지 상태로 생성** (사람이 확인 후 켜기)

### 범위 밖 (YAGNI)

- **쇼핑검색 세팅** - 소재가 상품 자체라 성격이 완전히 다르다. 네이버쇼핑 등록 상품 + 광고계정 연결이 전제라 "링크만 넣으면"이 성립하지 않는다. 대량등록 템플릿은 이미 확인해뒀으니(§6) v2에서 이어간다.
- 기존 캠페인에 그룹 추가 (신규 생성만)
- 확장소재 자동 등록 (F-AssetBulk가 이미 담당)
- 세팅 후 운영·최적화
- 다계정 일괄 세팅

## 3. 핵심 원칙 - AI는 설계자, 네이버는 사실 확인

F-Brief에서 세운 "AI는 분석가가 아니라 번역기" 원칙을 **여기서는 완화한다.** F-Brief는 광고주에게 그대로 나가는 보고서라 AI 판단을 최소화했지만, 여기는 **AE가 검토·수정하는 초안**이므로 AI가 훨씬 앞까지 나가도 된다.

경계는 이렇게 긋는다.

| AI가 판단 | 네이버가 확인 |
|---|---|
| 무엇을 파는가, 누구에게, 어떤 강점으로 | - |
| 그룹을 몇 개로, 어떤 축으로 쪼갤지 | - |
| 그룹 이름, 소재 제목·설명 | - |
| 시드 키워드 | - |
| **연관 키워드 중 이 상품에 맞는 것 선별** | - |
| 제외 키워드 (안 파는 것) | - |
| 키워드별 랜딩 URL 매칭 | - |
| - | **그 키워드가 실재하는가, 월 조회수 얼마인가** |
| - | 경쟁 정도 |
| - | 순위별 예상 입찰가 |

**철칙: 등록 대상 키워드는 100% 네이버 키워드 도구에서 나온 것이어야 한다.** AI는 시드를 주고 골라낼 뿐, 최종 목록에 AI가 만든 문자열이 들어가면 안 된다. 구현 시 "AI 응답의 키워드가 조회 결과 집합에 있는가"를 코드로 검증한다(F-Brief `brief-verify.ts`와 같은 계열).

## 5. 단계별 설계

### 5.1 페이지 읽기 (`page-read.ts`)

`naver-tag-picker`의 `src/lib/tags/product-tags.ts`를 이식한다. 핵심은 2단 폴백이다.

1. `window.__PRELOADED_STATE__` - 네이버 스토어에서 가장 풍부
2. **JSON-LD(`application/ld+json`)** - 표준이라 일반 쇼핑몰에도 상당수 통한다
3. 둘 다 실패하면 본문 텍스트를 잘라 AI에 넘긴다 (정확도는 떨어지지만 없는 것보단 낫다)

**차단 대응** (형제 프로젝트 실측, 상세는 `reference_naver_tag_picker`):
- background에서 직접 fetch하면 네이버가 **490**으로 막는다. 격리 world fetch로도 안 된다.
- **탭으로 여는 것(navigation)은 별개 경로라 막히지 않는다.**

그래서 이렇게 간다.

```
숨김 탭으로 열어 읽기
   ↓ 실패
탭을 앞으로 꺼내 사용자에게 보여줌 + "확인이 필요해요"
   ↓ 사용자가 캡챠·로그인 처리
자동 재개
```

**실패 원인을 분류하지 않는다.** 캡챠인지 로그인인지 구조 변경인지 판별하려 들면 그 코드가 계속 깨진다. 못 읽었으면 그냥 보여준다 - 사람이 보면 3초면 안다. (2026-08-13 사용자 결정: 캡챠·로그인은 이용자가 바로 처리하면 되므로 문제없음)

권한은 `<all_urls>`가 필요하다. 사내 배포라 심사가 없어 2026-08-13에 최소화 방침이 폐기됐다(루트 CLAUDE.md).

### 5.2 AI 상품 이해 (`product-understand.ts`) - **확인 게이트**

읽은 정보를 Edge Function에 넘겨 구조화된 이해를 받는다.

```ts
interface ProductUnderstanding {
  business: string;      // 업종 (예: "반려동물 사료 판매")
  product: string;       // 무엇을 파는가
  priceRange?: string;
  targets: string[];     // 누구에게
  strengths: string[];   // 강점·셀링포인트
  isLocal: boolean;      // 지역 기반 서비스인가
  seedKeywords: string[];// 시드 5~10개
}
```

**이 결과를 사용자에게 먼저 보여주고 확인받는다. 이 게이트가 이 설계에서 가장 중요하다.**

AI가 상품을 잘못 이해하면 그 뒤가 통째로 틀린 채 초안이 나온다. 그러면 AE는 키워드 200개를 훑다가 뒤늦게 "뭔가 이상한데"를 발견하게 된다. 한 줄짜리 이해를 먼저 보여주면 3초 만에 판별되고, 고치는 것도 "여기 남성용 아니라 여성용이야" 한마디면 끝난다.

수정은 자유 텍스트로 받아 다시 태운다.

### 5.3 초안 생성 (`draft.ts`)

```
시드 키워드 (AI)
   ↓ fetchRelatedKeywords - 시드마다 연관어 최대 1000개 + 조회수 + 경쟁도
후보 풀 (네이버 = 사실)
   ↓ 규칙 1차 필터 - 조회수 하한, 중복 제거, 명백한 무관어 제외
   ↓ AI 2차 선별 + 그룹 배분 - "이 후보들을 상품 이해에 맞게 골라 그룹에 나눠라"
   ↓ 코드 검증 - AI가 돌려준 키워드가 후보 풀에 전부 있는가 (없으면 버림)
확정 키워드 + 그룹 구조
   ↓ GET_BID_ESTIMATE - 그룹별 목표 순위에 맞는 입찰가
초안 완성
```

같이 만드는 것: 그룹 이름, 그룹별 소재(제목 15자 / 설명 45자, 네이버 제한 준수), 키워드별 랜딩 URL(대량등록 템플릿이 PC/모바일을 따로 받는다 - §6).

`fetchRelatedKeywords`는 배치 5개 + 429 backoff가 이미 들어 있으니 그대로 쓴다. `hintKeywords` 제약(한글·영문·숫자, ≤30자, 공백 불가)에 걸리는 시드는 미리 거른다.

### 5.4 검토·수정 (`draft-ui.ts`)

계층 트리로 보여주고 인라인 편집. 오버레이 UI는 `src/shared/CLAUDE.md`의 패턴을 따른다(다이얼로그 `wireBackdropDismiss`, 드롭다운 `createDropdown`, 스크롤 표는 분리형 헤더).

키워드 표는 **조회수·예상 입찰가·예상 순위를 같이 보여준다.** AE가 "이 키워드 빼자"를 근거를 보고 판단할 수 있어야 한다.

행 단위 삭제, 입찰가 일괄 조정, 그룹 이동, 소재 문구 수정.

### 5.5 자동 세팅 (`apply.ts`)

```
① 캠페인 1개 생성          화면 자동화
② 광고그룹 N개 생성 + 소재   화면 자동화 (N은 보통 3~5)
③ 그룹ID 조회              ncc/adgroups GET - F-Setup 코드 재사용
④ 키워드 CSV 1장 생성      mass-csv.ts (EUC-KR)
⑤ 대량관리 페이지에 업로드   input[type=file] 주입 - F-AssetBulk 방식
⑥ 결과 확인
```

**①②는 미정찰이다.** F-AssetBulk가 확장소재 모달 자동화를 이미 해냈으니 같은 방식으로 가능하다고 보지만, 캠페인·그룹 생성 화면의 DOM은 아직 안 봤다. 구현 첫 단계에서 정찰한다.

③이 ⑤보다 먼저 와야 한다 - **키워드 템플릿의 광고그룹ID가 필수**라 그룹이 존재해야 키워드를 올릴 수 있다. 이 순서 의존은 오히려 이득이다. 중간에 그룹ID가 손에 들어오므로 되돌리기 대상이 명확해진다.

## 6. 대량관리 사양 (2026-08-13 라이브 정찰)

페이지 `/manage/ad-accounts/{adAccountNo}/sa/tool/mass` (Easy 탭만 `/sa/tool/bulk`)

| 탭 | 실제 범위 |
|---|---|
| 대량 등록/수정/삭제 | 광고유형(파워링크 `WEB_SITE` / 쇼핑검색 `SHOPPING`) × 작업(키워드 등록 / 키워드 입찰가 수정). **이게 전부** |
| 대량 광고그룹 복사 | 기존 그룹 → 다른 캠페인. 키워드·소재·확장소재 포함 선택, 최대 100개. **"복사한 광고그룹을 OFF합니다" 옵션 내장** |
| Easy 대량 관리(beta) | 추가제목·추가설명 등록만 |
| 광고 다운로드 | 내보내기 |

> 블로그·마케팅 매체가 "캠페인명·광고그룹명·제목·설명·랜딩URL을 다 넣는다"고 쓰는 건 **구 광고관리시스템** 얘기다. 신 관리자엔 해당 없음.

### 키워드 등록 템플릿 (CSV, 엑셀 아님)

정적 파일이라 인증 없이 받는다.

- 파워링크 `/apis/sa/file/static/ko_add_keyword_template.csv`
  ```
  광고그룹ID(필수) | 키워드(필수) | PC URL(선택) | 모바일 URL(선택) | 키워드입찰가(선택,숫자만)
  ```
  그룹 URL이 1개여도 PC/모바일에 같은 값을 2번 넣는다.
- 쇼핑검색 `/apis/sa/file/static/ko_add_brand_keyword_template.csv` (파일명에 brand가 붙지만 쇼핑검색용, v2 참고)
  ```
  광고그룹ID(필수) | 키워드(필수) | 키워드유형(필수: 자사1/타사2/일반0) | 키워드입찰가(선택)
  ```
  입찰가 최소 300원.

### 함정 3개 (전부 실측)

1. **인코딩 EUC-KR.** UTF-8로 만들면 한글이 깨진다. 브라우저에 EUC-KR 인코더가 없으므로 변환 테이블이 필요하다 - `mass-csv.ts`가 담당.
2. **1~6행은 안내문, 삭제 금지. 7행부터 데이터.** 템플릿을 받아 그 앞부분을 그대로 두고 뒤에 붙이는 게 안전하다.
3. 한 파일 최대 10,000행, 광고그룹당 키워드 1,000개.

### 업로드

`<input type="file" accept=".csv" name="file">` - 평범한 파일 입력이다. `image-file.ts`가 하는 것처럼 `File` 객체를 만들어 주입하면 된다.

### DOM 함정

ads.naver.com의 select는 네이티브가 아니라 antd 계열이다. 옵션은 `.ad-cms-select-item-option`(내부 `.ad-cms-select-item-option-content`), 선택값은 `.ad-cms-select-selection-item`. **일반 click이 안 먹어** `mouseover→mousedown→mouseup→click`을 직접 dispatch해야 한다. asset-bulk의 `selectPromoKind`가 같은 계열 문제를 이미 푼다.

## 7. 안전장치

돈이 나가는 기능이라 여기를 얇게 만들면 안 된다.

1. **일시중지로 생성.** 만들고 사람이 확인한 뒤 켠다. 그룹 복사에 OFF 옵션이 있는 걸로 봐 네이버도 같은 전제다.
2. **되돌리기.** 만든 캠페인·그룹·키워드 ID를 전부 기록해두고 한 번에 지운다. ③단계에서 그룹ID가 손에 들어오므로 대상이 명확하다.
3. **키워드 검증.** AI가 돌려준 키워드가 조회 결과 집합에 없으면 버린다(§3 철칙).
4. **입찰가 상한.** 초안 단계에서 그룹별 일예산 대비 비정상 입찰가를 경고한다.
5. **부분 실패 처리.** 대량등록은 신청건수/성공건수/실패건수와 결과 파일을 준다. 실패분을 읽어 사용자에게 한글로 보여준다.

## 9. 검증

### 자동
- `mass-csv.ts` - EUC-KR 인코딩, 1~6행 보존, 1만행 분할, 그룹당 1000개 상한 (vitest)
- 키워드 검증 - AI 응답에 없는 키워드가 섞였을 때 걸러지는가 (vitest)
- `page-read.ts` - `__PRELOADED_STATE__` / JSON-LD / 실패 3경로 (고정 HTML 픽스처)

### 수동 (필수)
- 네이버 스토어 상품 링크 1개 → 세팅 완료 → 광고관리자에서 실물 확인
- 일반 자사몰 링크 1개 → 상품 이해가 말이 되는가
- 캡챠·로그인 페이지 → 탭이 앞으로 나오고 처리 후 재개되는가
- 키워드 1000개 초과 → 그룹 분할 또는 경고
- 되돌리기 → 만든 것이 전부 지워지는가
- 한글 키워드가 대량등록 후 안 깨지는가 (EUC-KR 검증)
